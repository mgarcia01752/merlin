# MERLIN terminology

Open this guide from **About → Terminology** in the workbench. That menu opens
this Markdown page on GitHub in your default browser and requires internet access.
Definitions below describe the terms used in MERLIN; linked guides explain the
supported implementation and its limits.

## Workbench and signal path

| Term | Meaning |
| --- | --- |
| Channel | Applies the configured response and noise between transmitter and receiver. |
| Awaiting results | Neutral upstream PRBS-RX status before an actual report exists. Start produces the independently verified result; loading alone does not pass verification. See the [upstream workbench](upstream-workbench.md#edit-accepted-settings). |
| CM | Cable modem. PNM input files represent measurements collected by a modem; MERLIN does not control or capture from a modem. |
| CMTS | Cable Modem Termination System. In MERLIN, it transmits the supported downstream OFDM signal and receives the supported upstream OFDMA signal; CMTS configuration remains separate from the upstream payload source. |
| CPA | Common Path Attenuator: adjustable scalar loss in the shared channel path before the receiver. Configured in dB (0–60); applies to the complete waveform, not individual profiles. |
| DOCSIS | Data Over Cable Service Interface Specifications, the cable-access specification family. |
| MCE | MERLIN Channel Estimation: optional receiver-owned pilot channel estimation and received-only decoder reliability. Select Pilot-based channel and noise estimation (MCE) under Receiver mode; Supplied CM channel estimate is the default. An MCE chip on the main Receiver block indicates enablement. See the [MCE guide](receiver-estimation/mce.md). |
| MERLIN | Modulation, Encoding, Reception, Link Impairments & Noise. |
| PHY | Physical layer: coding, modulation, waveform transmission and reception. |
| Not used | Neutral status for optional RxMER when an accepted upstream configuration uses no RxMER target. The ideal simulation can run without that measurement. See [workbench examples](workbench-examples.md#upstream-examples). |
| Presentation limit | A cap on retained view text, array/object entries and open/retained views. A rejected optional display preserves its previous observation; hidden data can remain retained after closing. See [presentation limits](workbench.md#presentation-limits). |
| PRBS15 | A repeatable pseudorandom binary sequence generated by a 15-bit shift register. Its sequence period is 32,767 bits. It supplies test traffic and is separate from PHY scrambling. |
| PRBS-RX / comparison | Independently compares decoded payload bits with the original accepted source. It does not feed expected bits into decoding. |
| Receiver (RX) | Processes received samples, recovers signaling and decodes payloads. |
| Resource grid | Original frame-symbol and physical-carrier positions with authoritative upstream allocation/pilot roles. The [configured view](upstream/resource-grid.md) precedes transmit correction and is not an observed waveform. |
| Retained-data limit | A cap on data admitted for continued use by an application session. Receiver Apply rejected at this admission step preserves its accepted options and previous result. See the [run controls](workbench.md). |
| Snapshot | A bounded retained observation, not the entire history of a simulation. A missing snapshot is not automatically a processing failure. |
| Source / PRBS-TX | Original traffic before encoding. The Source stage uses the accepted PRBS-TX settings: generated PRBS15, or exact file bits with optional PRBS fill. It is not the NCP/PLC control source. |
| Test point (TP) | An inspectable boundary between processing stages. A selected instrument reads retained data from that boundary. |
| Transmitter (TX) | Encodes source bits, maps modulation cells and produces an OFDM waveform. |
| Workbench (WB) | The main diagram, configuration blocks, instruments and run controls. A saved WB contains accepted settings and embedded original input bytes. |

See the [workbench](workbench.md), [source editor](source-input.md) and
[transmitter stages](transmitter-workbench.md).

## OFDM and waveform terms

| Term | Meaning |
| --- | --- |
| Baseband | A frequency representation centered around zero, before RF upconversion. |
| Cell | One modulation value associated with a subcarrier during one OFDM symbol. Cells are reordered by interleaving. A data cell holds one QAM symbol; it is not an entire OFDM symbol or a codeword. |
| Complex baseband | Baseband represented as I/Q. It retains phase and distinguishes positive and negative frequency offsets. “Complex” describes the representation, not another frequency band. |
| Cyclic prefix (CP) | A cyclic extension preceding the useful symbol interval, helping accommodate delayed channel energy. |
| FFT / IFFT | Fast Fourier Transform / inverse FFT. The receiver converts time samples to subcarrier values; the transmitter performs the inverse operation. |
| Flat guard time | In MERLIN's timing panel, the cyclic-prefix interval remaining after the configured roll-off interval. It is an ideal timing budget, not guaranteed echo protection. |
| I/Q | In-phase and quadrature components: the real and imaginary coordinates of a complex sample or modulation value. |
| Interleaver depth | How many OFDM-symbol periods the time interleaver spreads cells across. More depth increases its delayed history and the drain needed at the end. |
| Interleaver drain / Draining | Flushes delayed cells through the interleaver/deinterleaver after the observation and queued-payload completion. The receiver can still recover original payloads while observation-symbol count stays fixed. See [details](#interleaver-drain). |
| Interleaving | Reorders bits or cells to spread localized impairments. Bit interleaving and time/frequency cell interleaving operate on different objects. |
| OFDM | Orthogonal Frequency Division Multiplexing: many orthogonal subcarriers transmitted together. |
| OFDM symbol | One time step containing the subcarriers together. Its transmitted waveform includes the useful FFT interval and the configured cyclic prefix/window treatment. |
| Pilot | A known reference signal used for tasks such as tracking and channel estimation. Continuous and scattered pilots occupy different patterns. |
| Roll-off period (RP) | The transition interval used by the transmit window to smooth symbol boundaries. |
| Sample rate | Number of time-domain samples per second, shown in MS/s for millions of samples per second. |
| Subcarrier | One frequency position in the OFDM grid. Depending on configuration and time, it can carry data, control, a pilot or no signal. |

See [transmission settings](transmission.md), [waveform stages](waveform/README.md)
and the [Spectrum Analyzer](spectrum-analyzer.md).

## QAM and decisions

| Term | Meaning |
| --- | --- |
| Cell label | An integer identifying the selected QAM point before mapping to I/Q. For 256-QAM, labels range from 0 through 255. The label is not a subcarrier index. A separate label snapshot is unavailable on the current profile-based TX path; mapped I/Q remains inspectable. |
| Constellation | A plot of I/Q values. Ideal modulation points form the reference pattern; noise and distortion can displace received points. |
| Data / NCP colors | Mixed TX QAM plots use green squares for data and red circles for NCP, with a legend. These colors indicate roles, not success/error status. |
| Decision boundary | A dividing line between regions assigned to neighboring constellation points by the slicer. Crossing one can change the hard symbol decision. |
| Derandomized LLR | Actual receiver soft evidence after the PHY randomizer mask is reversed. It remains separate from raw demapper evidence and independent source comparison. See [upstream soft views](upstream/instruments.md#ldpc-and-soft-observations). |
| Filler | Explicit non-payload cells used where the transport requires them. Mixed TX plots show retained filler as amber diamonds. Missing history is separate and is not plotted as zero-valued I/Q. |
| LDPC input LLR | Actual soft evidence passed to a completed LDPC decoder call at transmitted-bit positions. It excludes internally restored shortened priors and is not a posterior metric. See [upstream soft views](upstream/instruments.md#ldpc-and-soft-observations). |
| LLR | Log-likelihood ratio: soft evidence for a bit being zero versus one. In MERLIN's LLR view, positive favors zero and negative favors one; larger magnitude indicates stronger evidence under the model. |
| QAM | Quadrature Amplitude Modulation: information represented by a set of I/Q constellation points. |
| QAM order | Number of available constellation points. 256-QAM carries 8 coded bits per data cell; 4096-QAM carries 12. These are coded bits, not net payload bits after FEC overhead. |
| QAM slicer / hard decision | Selects a constellation label from a received I/Q value. It differs from the soft information supplied to FEC decoding. |
| QAM symbol | One selected constellation value. Distinguish it from an OFDM symbol, which contains many subcarrier values. |

“Cell words,” “bits per cell” and “output data cells” are DOCSIS PHY terminology:
CM-SP-PHYv3.1-I20-230419, §7.5.5, Table 31, PDF page 120. This terminology was
checked against the repository's text extract, not a rendered PDF.
See [QAM processing](qam-processing/README.md) and [receiver instruments](receiver-workbench.md).

## Configuration, signaling and measurements

| Term | Meaning |
| --- | --- |
| Channel estimate H | Complex frequency response across subcarriers. Flat/unity H = 1 + 0i means no gain/phase change; H = 0 + 0i would suppress the signal. |
| Combined Channel Response | Predicted gain from accepted channel settings before receiver correction. Tilt/cable loss and echo responses compose as complex products, not by adding I/Q gains. This preview is separate from received measurements and the MCE estimate. See [channel models](impairments/waveform-filter.md#combining-loss-and-echoes). |
| DPD | Downstream Profile Descriptor: profile-specific modulation assignments. The DPD input editor imports modulation-profile PNM data; the TX message inspector shows actual generated DPD signaling packets. They are different file/message representations. |
| Echo | A delayed copy of the signal. An impulse-response peak is not automatically a uniquely identified physical reflector. |
| Equalization | Applies a correction based on channel response to reduce its effect on received constellation points. |
| FIR | Finite impulse response: a filter formed from a finite set of delayed, weighted samples. MERLIN's [waveform channel](impairments/waveform-filter.md) retains those delays between OFDM symbols. |
| NCP | Next Codeword Pointer: control signaling that identifies codeword placement and related transport information. NCP is distinct from payload data. |
| Nearest-point estimate | MER calculated using the nearest ideal constellation point instead of the actual transmitted symbol. Dense QAM and wrong decisions can make it too optimistic. |
| Noise Seed | Starting value for the simulated noise generator. The same seed and configuration repeat the noise pattern; a different seed changes the pattern at the same target noise level. Separate from PRBS data generation. See [run settings](workbench-configuration.md#run). |
| OCD | OFDM Channel Descriptor: common channel configuration carried in downstream signaling. |
| Pilot-assisted estimation | Uses independently known pilot symbols to estimate the received channel; it is not arbitrary blind RF acquisition. |
| PLC | Physical Link Channel: protected signaling used to acquire and configure downstream OFDM reception. |
| PNM | Proactive Network Maintenance. MERLIN uses supported existing PNM captures as simulation inputs. |
| Profile | A set of modulation assignments over the channel's subcarriers. An imported profile is not automatically supported for a live run. |
| Random variation | Independent Gaussian offsets in dB around a synthetic flat RxMER baseline. Standard deviation sets the spread; the designer seed reproduces the pattern. It is separate from waveform noise. See [RxMER Designer](measurement-inputs/rxmer-designer.md#starting-values-and-random-variation). |
| Receiver estimate Ĥ (H-hat) | Channel response estimated from received pilots, distinct from applied H. The response Display selector calls it MCE Estimate for MCE runs and Pilot Estimate for legacy pilot-estimated runs. See the [MCE guide](receiver-estimation/mce.md). |
| Run Profile | The captured profile ID used by one independent simulation run. It is separate from the current on-wire Profile A/ID0. |
| RxMER | Receive Modulation Error Ratio: per-subcarrier signal-to-modulation-error power ratio, commonly expressed in dB. MERLIN uses it to model residual error power; it does not reconstruct measured I/Q from RxMER. |
| TLV | Type-Length-Value: a tagged field containing its type, value length and value bytes. Decoded child fields in the inspector are not necessarily nested TLVs. |
| TX-reference MER | Modulation error ratio calculated against the actual transmitted symbol at the same physical bin and time. In the QAM analyzer the reference is diagnostic only; it is never supplied to the receiver. |
| Velocity factor (VF) | Signal propagation speed in the cable divided by the speed of light. Reflector-distance estimates assume an out-and-back path. |

See [measurement inputs](channel-measurements.md), [TLV inspection](transmitter-workbench.md)
and [receiver channel estimation](receiver-estimation/README.md).

## Coding, results and analyzer units

| Term | Meaning |
| --- | --- |
| Active elapsed (upstream) | Time used by an upstream execution, excluding acknowledged pauses. It is separate from simulated waveform duration. See [upstream execution](upstream-workbench.md#run-and-inspect-results). |
| BCH / LDPC | Bose–Chaudhuri–Hocquenghem / Low-Density Parity-Check coding. MERLIN uses both in the supported payload coding chain. |
| BER | Bit Error Rate: compared bit errors divided by compared bits. With no compared bits, BER is unavailable, not zero. |
| Capture frequency mapping | Labels baseband bins using the capture's frequency origin. It does not upconvert the simulated signal. |
| Codeword | A block produced by an error-correcting code. One codeword can span many modulation cells and multiple OFDM symbols. |
| Decoder iterations | Repeated LDPC decoding steps. More iterations mean more decoder work; reaching a limit does not by itself describe every BCH or payload outcome. |
| ENBW | Equivalent Noise Bandwidth: the effective noise bandwidth of the FFT window. It differs from the frequency spacing between FFT bins. |
| FEC | Forward Error Correction: adds redundancy so a receiver can detect/correct errors. |
| Observation duration | Source observation interval configured in Configure WorkBench. Acquisition and completion/drain can add processing beyond that interval. |
| Ordered frame diagnostic | Analyzes consecutive retained frame-stage samples while keeping their original physical gaps or overlaps distinct from a continuous waveform. See [Spectrum Analyzer sampling](spectrum-analyzer.md). |
| PSD | Power Spectral Density: power per unit frequency. MERLIN's time-sample SA shows normalized dB/Hz or dBmV/Hz when an explicit electrical reference is accepted. This does not imply RF upconversion or a dBm measurement. |
| Spectrum Analyzer (SA) | Displays power versus frequency for a selected test point. TX and RX instruments use distinct retained boundaries. |

See [FEC](fec-codec.md), [run/results](closed-loop-workbench.md) and the
[Spectrum Analyzer guide](spectrum-analyzer.md). Return to the
[documentation index](../README.md).

## Interleaver drain

An interleaver deliberately delays some cells so neighboring source data travels
in different OFDM symbols. When the requested observation ends, some original
data can still be inside those delay lines. **Interleaver drain** sends the
remaining delayed cells through the receive path so that data can be recovered.
It does not create another observation interval or fabricate new source payloads.

For an already active stream, MERLIN's current time-interleaver model uses
**depth minus one drain symbols**: depth 16 needs 15 drain symbols, while depth 1
needs none. Increasing depth therefore increases this drain tail. This is the
implemented model, separate from waveform-tail samples and the earlier completion
phase that finishes placing already queued payload words.

The **simulated duration** of that tail depends on symbol timing. The **wall time**
to process it also depends on decoder iterations, modulation/profile loading,
channel conditions and CPU availability. Twice the depth does not imply exactly
twice the wall time. While Draining, the observation-symbol counter stays fixed;
recovered payloads and elapsed time can continue increasing.

See [elapsed time and slow profiles](closed-loop-workbench.md#elapsed-time-and-slow-profiles)
and [FEC Monitor](fec-monitor.md). Implementation references:
[paired delay](../../crates/ofdm/src/signal_processing/interleaving/settings.rs) and
[payload drain](../../crates/ofdm/src/simulation/payload/transmitter.rs).

## Single Shot and Replay selection

**Single Shot** holds one selected RxMER capture for each profile's run.
**Replay** uses the checked captures in listed order at the configured OFDM-symbol
interval. **Replay capacity** is how many capture transitions fit in the CWB
observation duration per profile; loaded captures may exceed that number.
Checking captures selects simulation inputs; clicking filenames previews them.
See [RxMER selection](channel-measurements.md#choose-captures-for-the-next-run).

**CWB (Configure WorkBench)** contains the accepted run duration and profile
selection. Replay capacity uses its duration for one profile; a sweep runs that
window separately for each selected profile.

## Bit raster and carrier map

A **bit raster** displays consecutive bits in rows, using different colors for
zero and one. Read left to right, then top to bottom; the transmitter's LDPC view
shows coded bits rather than a recovery or error-rate measurement.

A **carrier map** shows the physical OFDM subcarriers and their assigned roles
for one symbol. Its Data locations may carry transported NCP. The transmitter
map overlays relative bin power; it is not a time waterfall or an RF PSD estimate.
See [transmitter graphs](transmitter-workbench.md).

## Workbench loading activity

An **activity bar** moves while a workbench opens. It indicates ongoing work
without estimating a completion percentage. In **--debug-ui** mode,
**Time since Open** counts real
time, including file selection, reading and capture validation. It is separate
from simulated duration and does not predict time remaining.
See [opening workbenches](workbench.md#workbench-configuration-files).

## Transmit window overlap

The **transmit window** weights the samples near the start and end of each OFDM
symbol. Adjacent symbols overlap during the roll-off interval: one window fades
out while the next fades in. Their weights add to one over that shared interval;
this does not mean the RF signal amplitude or power is constant.
See [symbol timing](spectrum-analyzer.md#symbol-timing-and-cable-echo-budget).

### RxMER Designer

An editor for deliberately designed MER profiles or capture sequences. It retains
original baselines and stores the recipe separately from measured source data.
A **capture** is one frequency array; a **subcarrier** is one frequency position
inside that array. **Crest spacing** is the frequency separation between adjacent
ripple peaks. The echo-distance helper assumes a round-trip cable cavity; it
infers spacing only. A **synthetic notch** is a reduction in MER over a band,
not a cellular waveform or a phase response. The **PLC region** is one continuous
chart band from the first to the last PLC carrier in the accepted modulation
profile. See [RxMER Designer](measurement-inputs/rxmer-designer.md).

### MSI and UAC

MSI is the Windows Installer package used to install or upgrade MERLIN. UAC
(User Account Control) is Windows' administrator-approval prompt. MERLIN Update
requests that approval only for the installer and reopens the app as your normal
user. See [Windows installation and updates](install/windows.md).

### RxMER export rounding and clamping

**Rounding** stores designed RxMER in PNM binary's nearest quarter-dB step;
positive half steps round upward. **Clamping** explicitly limits binary readings
to 0–63.5 dB and reports changed samples. JSON keeps full-precision finite values
and missing nulls. Neither operation changes the original data. A **provenance
manifest** records sources, recipe and output hashes and identifies designed
captures. See [Designer Save](measurement-inputs/rxmer-designer.md#save-designed-captures).
